# Residual-risk register (SAD §11/§15/§16 closure)

The task register (**RT-01 … RT-59**) is resolved in
[`SAD_09_Completion_Plan.md` Appendix 5](../dev/markdown/SAD_09_Completion_Plan.md#appendix-5--task-identifiers-rt-nn-and-rc-nn),
which records each task as closed or carried by an `RF-*` item. This register tracks
the **SAD-declared residual risks**: the design authors' own
admissions of known gaps, technical debt, and roadmap items. Each has a status so a
GA reviewer sees, at a glance, what is controlled, what is partly controlled, what is
a deliberately accepted residual, and what remains open.

**Grading.** Every row is graded against the RF item that carries it in the
[completion plan](../dev/markdown/SAD_09_Completion_Plan.md). A row is **PARTIAL**
when the control it cites exists only as a tested library that no running service
uses, runs against a stand-in, or has a known defect. Ten of the fifteen High-severity
rows are PARTIAL.

## Status legend

| Status | Meaning |
|--------|---------|
| **MITIGATED** | A concrete, implemented and tested control addresses the risk where the risk arises. The residual (if any) is stated. |
| **PARTIAL** | A control exists but does not yet address the risk in a deployment: it is a library no running service uses, it is tested only against a stand-in, or it has a known defect. The row says what exists, what is missing, and which `RF-*` item carries it. |
| **ACCEPTED** | A residual risk that is inherent (performance, external process, or a fully-compromised host outside the trust boundary). A compensating control limits it; it is accepted, not eliminated. |
| **OPEN** | Not yet built, or an external activity (e.g. a certification lab) that must complete before GA. |

**What MITIGATED means here.** MITIGATED means the *control* is implemented and tested in this
repo. Controls whose full assurance is also a deployment/lab activity (real HSM
custody, FIPS module certification, GPU inference) are marked with a **†**; that part
is gated by the deployment-tier suite (RT-40), in which RC-40.3 (HSM) and RC-40.4
(GPU) have so far only been skipped.

The limits are sizes, not admission control: a sustained load at the limit is refused or OOM-killed in that container. |

| CI runner compromise | Med | **PARTIAL** | *Exists:* every GitLab job image and service is pinned by digest, and `tools/ci/pipelines.sh --check` refuses one that is not, as it refuses a GitHub action not pinned to a commit. GitLab merge-request jobs run unprivileged inside the digest-pinned toolchain image, whose first step checks `MIDGARD_TOOLCHAIN_DIGEST` against `tools/ci/toolchain.digest` and fails closed; only `toolchain-publish` and `acceptance` use privileged Docker-in-Docker, on protected refs (VLD-ANB-MIDGARD-0022, VLD-ANB-MIDGARD-0043). | Bearer token theft after sign-out | High | **MITIGATED** | Every session token carries a random id; `POST /api/v1/logout` revokes the presented token and the gateway refuses a revoked token, or one whose subject is no longer enrolled, on every request. A state directory journals revocations under the issuer key, so they survive a restart. The console keeps the token in memory only, not in web storage (VLD-ANB-MIDGARD-0021; `services/http-gateway/tests/session_revocation.rs`). Residual: a token still lives for one hour unless signed out; a reduced role takes effect at the next sign-in (the token carries no role version); there is no administrator route to revoke another principal's sessions; the revocation journal is append-only and is not compacted. |
| Development mode and plaintext edge defaults | High | **MITIGATED** | The gateway edge speaks plaintext HTTP. Development mode, with its compiled-in demo logins, starts only with the explicit `--dev` flag and listens on loopback only, with no override; no arguments or a bare address is a usage error, and the release image entrypoint refuses to start a service with no arguments (MG-SEC-06). A state-directory gateway refuses a non-loopback bind unless `--allow-non-loopback` is given (`check_bind`, `cli_modes.rs`). The console refuses a plaintext gateway URL off loopback in the SDK (`assertSafeBaseUrl`), at start-up, in the Vite build and in the console image build. The console's nginx sends CSP (with `form-action 'self'`), Permissions-Policy, Referrer-Policy, X-Frame-Options and COOP on every location from one shared file (VLD-ANB-MIDGARD-0014, -0032, -0085). Residual: TLS termination in front of the edge is a deployment responsibility, enforced only by the refusal of non-loopback binds and URLs; an operator who passes `--allow-non-loopback` without a terminator exposes plaintext credentials. The demo credentials stay compiled into release builds, reachable only through `--dev` on loopback. The console CSP keeps `style-src 'unsafe-inline'` because the design system renders `<style>` elements for its keyframes (`BreakGlass`, `SyncStatus`, `StatusPill`); removing it needs those moved into the stylesheet. |
| Federation assertion replay | Med | **PARTIAL** | *Exists:* `PqFederation::verify` (`services/iam/src/federation.rs`) binds every upstream assertion to a configured issuer and audience, refuses a validity window longer than 300 s, an assertion more than 60 s ahead of the clock or past its expiry, and a nonce already accepted; the replay cache is bounded at 4096 live nonces and fails closed when full rather than evicting one. An assertion in the earlier unscoped shape is malformed. Tested in `services/iam/tests/federation.rs` (VLD-ANB-MIDGARD-0049). *Missing:* the library is not wired into any service, so the control does not yet act in a deployment; the replay cache is per process, so a deployment must route every federated login through one shared `PqFederation`. |
| **Registry tag substitution** | High | **MITIGATED** | The verifier, its key and the entrypoint travel inside each service image, so a tag moved in the enclosure registry could substitute an image that skips the check. The release chart pins every image by digest and does not render without them (`deploy/helm/midgard/templates/workload.yaml`); `deploy/helm/set-digests.sh` lifts the digests from the signed `images.lock`, and the release signs the digest-pinned values and rendering; the acceptance probes are applied only by digest (VLD-ANB-MIDGARD-0012, `tools/ci/tests/helm-digests.test.sh`). Residual: the committed development rendering `deploy/k8s/enclosure.yaml` uses tags, pulled every time, until the first release; no admission policy in the cluster requires digests. |
| Unauthenticated health and metrics ports | Med | **ACCEPTED** | `/healthz`, `/readyz` and `/metrics` (9090) carry no identity check, so the orchestrator and an in-enclosure scraper can reach them. Compensating: under Kubernetes each binds the pod address and its NetworkPolicy admits only the labelled scraper (`scraper.podLabel`) and any `scraper.nodeCidrs`; a wildcard `from` refuses to render, and `tools/ci/tests/k8s-ingress.test.sh` fails on a from-less ingress rule (VLD-ANB-MIDGARD-0027). Residual: under compose they bind `0.0.0.0:9090` on the internal, unpublished mesh network, so any container on that network can read counters and readiness; bearer or mTLS on `/metrics` is deferred, as it changes the Prometheus and kubelet contract. |
| Password KDF | Med | **MITIGATED** | New passwords are Argon2id at m=19 MiB, t=2, p=1 (`services/iam/src/password.rs`); a stored hash outside the cost floors or ceilings is refused before any work, so an edited directory entry can neither be weakened nor stall a sign-in; a legacy PBKDF2 entry (210,000 iterations) still verifies and is re-hashed to Argon2id at its owner's next successful sign-in (MG-SEC-11, VLD-ANB-MIDGARD-0025). Residual: legacy PBKDF2 hashes persist until each principal next signs in, and development mode (`--dev`, loopback only) deliberately uses a cheap PBKDF2 setting for its demo logins. |
| TOTP replay | Med | **MITIGATED** | A one-time code is accepted once (RFC 6238 section 5.2). The identity directory keeps, per principal and across restarts, the step of the last code accepted, and the authenticator refuses a code for that step or an earlier one. The gateway records the step under the same directory lock as the check and before the token leaves, so two logins with one code cannot both succeed, and a login whose step cannot be recorded fails closed; a wrong password consumes nothing (VLD-ANB-MIDGARD-0026). The administrator TOTP shares this verifier and persists the step the same way, in its own sealed journal (VLD-ANB-MIDGARD-0008). Residual: someone who observes a code before its owner uses it can still log in with it once, given the password, and the owner's own login with that code is then refused. Each accepted code appends one small record to the directory journal, which is not yet compacted. |
| WebAuthn verifier completeness | Low | **MITIGATED** | The principal passkey verifier (`services/iam/src/mfa.rs`) performs the assertion checks of WebAuthn Level 2 section 7.2: client data parsed at the edge with the shared, depth-limited JSON parser (`services/http-gateway/src/webauthn_client_data.rs`, no substring matching), type `webauthn.get`, challenge, an exact origin allow-list, RP id, user presence, user verification when the policy requires it, signature, and a signature counter that must increase, persisted per passkey in the identity directory (tagged record version 4). The default policy names no origin, so nothing verifies until a relying party configures one. User verification is a precondition the policy can demand, never a factor of its own (as for administrators, WP-10). Tests: `webauthn_origin_mismatch_is_refused`, `webauthn_uv_is_required_by_policy`, `webauthn_sign_count_must_increase`, `client_data_type_and_challenge_are_read_from_parsed_json`, `a_passkey_sign_count_survives_a_restart` (VLD-ANB-MIDGARD-0084). Residual: passkey registration (COSE/CBOR attestation) is still out of scope and no browser flow uses the verifier; each accepted assertion appends one small record to the directory journal, which is not yet compacted. |
| **FIPS KAT certification before GA** | n/a | **OPEN** | The ACVP KATs run in-repo (`fips_backend`, `aead_kat`, `agility_fips`); **formal FIPS 140-3 module certification is an external lab activity** and is SAD_00's explicit GA bar. The primitives, their known-answer vectors (`hash_kat`, `hybrid_kat`) and the open questions for the independent cryptographic review are listed in `docs/security/CRYPTO_REVIEW_HANDOFF.md` (VLD-ANB-MIDGARD-0024, VLD-ANB-MIDGARD-0059). GA blocker. |
| Hand-rolled JSON parsers (six copies) | Med | **MITIGATED** | Six recursive-descent JSON parsers exist, each its crate's own: `services/runtime` (the gateway's request bodies and the deployment files), `crypto/attest`, `admin/ai-assist`, `bifrost/risk`, `forge/ai-assist` and `heimdall/decision-support`. Unbounded recursion let one unauthenticated request body abort the gateway (VLD-ANB-MIDGARD-0006); all six now refuse nesting deeper than 64 levels (`MAX_DEPTH`), each with a test, and `services/http-gateway/tests/security_edge.rs` proves the edge answers 400 and stays up. Residual: six copies can drift apart; consolidating them into one crate is deferred, since it touches six crates and their deployment-file loaders. [VLD-ANB-MIDGARD-0006] |
| Password spraying across names from one address | Med | **MITIGATED** | A failed login counts towards a lock on its name, but a spray tries one password against many names and never trips one. The edge now gives each source address a token bucket shared by the login and administration routes (a burst of 20, refilling at 0.5 a second; `--login-burst`, `--login-per-sec`): past it an attempt is answered 429 before any password is checked, and the ledger records the throttled source once a minute with the count suppressed, not one row per probe. Login fields are bounded first (128-byte username, 1,024-byte password), so neither the throttle nor the ledger can be grown by a hostile value. `services/http-gateway/tests/security_edge.rs` proves the burst, the coalesced row and the administration routes. Behind the operator's terminating proxy, `--trusted-proxy IP` charges each client to the address the proxy appended to `X-Forwarded-For`; the header is ignored from any other peer, and the bucket is never keyed on the username. Residual: under compose every client reaches the edge through docker-proxy from one address, as it does behind a proxy that is not named, so the per-source bucket is one for the whole site there: it still bounds the spray rate, but 20 wrong attempts anywhere throttle every user's login for a few seconds, and a spray from many addresses is limited only per name. Throttle state is in memory and a restart clears it. [VLD-ANB-MIDGARD-0005] |
| Anyone can lock an operator's login | Med | **ACCEPTED** | The lockout is per name, so anyone who can reach the edge can lock any name, an operator's included, by failing its password six times, and keep it locked (30 s, doubling to 15 minutes) by failing again as each lock lapses. The lock is no longer bypassable: attempts are reserved under the throttle's lock before any password is checked, so concurrent guesses cannot exceed the free failures, no more than four are checked at once per name, and a flood of made-up names evicts unlocked entries first and never clears a live lock for its age (`login_throttle.rs` unit tests; `services/http-gateway/tests/security_edge.rs::parallel_wrong_passwords_cannot_exceed_the_free_failures`). Compensating: the per-source allowance (a burst of 20, refilling at 0.5 a second) bounds how fast one address can keep a name locked. Rejected: locking per (source, name) pair, because under compose every source is the proxy's one address, so it would weaken the credential-stuffing defence for nothing. Residual: a client with many addresses, or any client under compose, can deny an operator's login until a second-factor-only recovery path exists (WP-56 or later). [VLD-ANB-MIDGARD-0019] |
| Administrator challenge exhaustion | Med | **MITIGATED** | `POST /api/v1/admin/challenge` must be unauthenticated: the challenge is how an administrator proves who they are. A flood once evicted every outstanding challenge from a shared 256-entry table (VLD-ANB-MIDGARD-0020). Each challenge is now bound to the administrator the request names and answerable only by them; each holds at most four, a fifth replacing their own oldest; names with no passkey are given a nonce but take no table entry; and past a global ceiling of 1,024 a new administrator is refused with 429 rather than anyone's challenge dropped. `services/http-gateway/tests/admin_enrolment.rs` proves the binding, the per-administrator bound, the unknown names and the ceiling. Residual: administrator names are not secret, and naming one needs no passkey, so a client that keeps requesting challenges for one named administrator keeps replacing that administrator's own challenges and can stop them completing a request while it continues; the per-source allowance (burst 20, 0.5 a second) slows it from one address, but under compose every client shares one address and a flood from many addresses is not bounded per source. The other administrators are unaffected, so dual control can proceed with another. Challenges are in memory and a restart clears them. [VLD-ANB-MIDGARD-0020] |
| Unauthenticated `/metrics` on the edge | Low | **ACCEPTED** | `GET /metrics` on the HTTP edge (7710) is served without a token so an in-enclosure scraper can poll it. It is bounded: request metrics are labelled by matched route template, never the request path (`route_label`), every family holds at most 1,000 series with drops counted in `metrics_series_dropped_total`, and label values are cut at 256 characters, so a client can neither grow the gateway's memory nor read back what it or others sent (VLD-ANB-MIDGARD-0003; `services/http-gateway/tests/security_edge.rs`, `services/telemetry/tests/telemetry.rs`). Compensating: network restriction; in the Helm chart the default-deny NetworkPolicy admits 7710 only from `console-edge` pods (`deploy/helm/midgard/values.yaml`), and a proxy that publishes the edge should not forward `/metrics`. The 9090 health ports are a separate item (WP-32). Residual: anything that can reach 7710 reads route-level request counts, latencies, connection outcomes and the availability SLO. [VLD-ANB-MIDGARD-0003] |
| **Custody material and data at rest on Kubernetes** | High | **PARTIAL** | *Exists:* the chart's `secrets.provider` takes identities, keystore passphrases and seeds from the Secrets Store CSI driver or external-secrets, or from Kubernetes Secrets only with a recorded etcd-encryption acknowledgement (the render fails without it outside kind); each keystore passphrase is a Secret or remote key of its own, copied into pod memory owner-only; seeds carry keys, trust anchors, configuration and the empty governance ledger, never the directory, object store or journals; `deploy/kind/bootstrap-secrets.sh` refuses any context that is not `kind-*`; compose is for development and evaluation and the gateway holds `keys/` (WP-29, VLD-ANB-MIDGARD-0018). *Missing:* no SecretProviderClass, ExternalSecret store or etcd KMS v2 configuration has run against a real cluster (the chart renders them; the cluster operator supplies them); the external-secrets path still materialises Secrets in etcd; the kind cluster's etcd is unencrypted by design. |
| Personal-data erasure and retention (residency) | Low | **OPEN** | Every durable store is append-only: there is no subject erasure, export, compaction or retention enforcement, and a replaced record such as an earlier password hash stays in the journal. The residency and backup documents no longer claim deletion; [RETENTION.md](RETENTION.md) sets the retention targets and the controller's obligations, and the claims ledger records `personal-data-erasure` as spec (WP-29, VLD-ANB-MIDGARD-0070). Carried by the follow-on work package: per-record data keys with crypto-shred tombstones for the directory, object and dataset journals. The audit ledger is immutable by design. |

## SAD_02: Mimir

| Risk | Sev | Status | Control / rationale · residual |
|------|-----|--------|--------------------------------|
| Novel jailbreaks evade static guards | Med | **PARTIAL** | *Exists:* a deterministic pre-filter with de-obfuscation, applied to each untrusted item before composition (grounding fact, memory item, history turn, user message) and never to the trusted system, contract, policy or tool layers, with a sanitise rewrite that replaces only the offending item and exempts identifiers and hashes (VLD-ANB-MIDGARD-0078); the same pre-filter screens the agent's whole output, proposed actions included (VLD-ANB-MIDGARD-0077); a `Classifier` seam; and untrusted layers (grounding, memory, history, user text, and the feed, ledger, simulation, schema, release, page and on-device fields of every product assembler) are delimited and provenance-tagged (`mimir_prompts::delimit`: indented DATA blocks with a source tag and a per-request boundary, control and zero-width characters removed, fields bounded), so tenant text cannot forge a layer header (VLD-ANB-MIDGARD-0080); and the system prompt travels in the model family's own system turn (ahead of the user text in the one turn of a family with no system role), with every family control token (role and turn markers, BOS, EOS) in system or user text neutralised by the family adapter, so content cannot close its turn and open a system or assistant turn on an engine that parses special tokens (VLD-ANB-MIDGARD-0060). | **Autonomous action blast radius** | High | **PARTIAL** | *Exists:* in the governed loop a consequential action is proposed, human-authorised and then executed and audited, and an irreversible action forces a human gate even when pre-authorised (tested, in-process). Carried by RF-MI-4, RF-UID-3. |
| **Autonomy overreach** | High | **PARTIAL** | *Exists:* consequential actions fail closed without explicit human authorisation, with PQ-signed lineage (RT-44). In Heimdall an action's class comes from the deployment's action-type catalogue, not the proposer; a type the catalogue does not list is refused at proposal; every execution, informational included, needs a recorded human decision (`heimdall/workflow/src/engine.rs:182`); and the actuator re-checks the type and class against the catalogue (WP-64, VLD-ANB-MIDGARD-0045).
