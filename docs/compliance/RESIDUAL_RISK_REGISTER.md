# Residual-risk register (SAD §11/§15/§16 closure)

The task register (**RT-01 … RT-59**) is resolved in
[`SAD_09_Completion_Plan.md` Appendix 5](../dev/markdown/SAD_09_Completion_Plan.md#appendix-5--task-identifiers-rt-nn-and-rc-nn),
which records each task as closed or carried by an `RF-*` item. This register tracks
the **SAD-declared residual risks**: the design authors' own
admissions of known gaps, technical debt, and roadmap items. Each has a status so a
GA reviewer sees, at a glance, what is controlled, what is partly controlled, what is
a deliberately accepted residual, and what remains open.

**Grading.** Every row is graded against the RF item that carries it in the
[completion plan](../dev/markdown/SAD_09_Completion_Plan.md). A row is **PARTIAL**
when the control it cites exists only as a tested library that no running service
uses, runs against a stand-in, or has a known defect. Nine of the eleven High-severity
rows are PARTIAL.

## Status legend

| Status | Meaning |
|--------|---------|
| **MITIGATED** | A concrete, implemented and tested control addresses the risk where the risk arises. The residual (if any) is stated. |
| **PARTIAL** | A control exists but does not yet address the risk in a deployment: it is a library no running service uses, it is tested only against a stand-in, or it has a known defect. The row says what exists, what is missing, and which `RF-*` item carries it. |
| **ACCEPTED** | A residual risk that is inherent (performance, external process, or a fully-compromised host outside the trust boundary). A compensating control limits it; it is accepted, not eliminated. |
| **OPEN** | Not yet built, or an external activity (e.g. a certification lab) that must complete before GA. |

**What MITIGATED means here.** MITIGATED means the *control* is implemented and tested in this
repo. Controls whose full assurance is also a deployment/lab activity (real HSM
custody, FIPS module certification, GPU inference) are marked with a **†**; that part
is gated by the deployment-tier suite (RT-40), in which RC-40.3 (HSM) and RC-40.4
(GPU) have so far only been skipped.

| Hand-rolled JSON parsers (six copies) | Med | **MITIGATED** | Six recursive-descent JSON parsers exist, each its crate's own: `services/runtime` (the gateway's request bodies and the deployment files), `crypto/attest`, `admin/ai-assist`, `bifrost/risk`, `forge/ai-assist` and `heimdall/decision-support`. | Password spraying across names from one address | Med | **MITIGATED** | A failed login counts towards a lock on its name, but a spray tries one password against many names and never trips one. Login fields are bounded first (128-byte username, 1,024-byte password), so neither the throttle nor the ledger can be grown by a hostile value. `services/http-gateway/tests/security_edge.rs` proves the burst, the coalesced row and the administration routes. Residual: under compose every client reaches the edge through docker-proxy from one address, so the per-source bucket is one for the whole site there: it still bounds the spray rate, but 20 wrong attempts anywhere throttle every user's login for a few seconds, and a spray from many addresses is limited only per name. Throttle state is in memory and a restart clears it. [VLD-ANB-MIDGARD-0005] |
| Anyone can lock an operator's login | Med | **ACCEPTED** | The lockout is per name, so anyone who can reach the edge can lock any name, an operator's included, by failing its password six times, and keep it locked (30 s, doubling to 15 minutes) by failing again as each lock lapses. The lock is no longer bypassable: attempts are reserved under the throttle's lock before any password is checked, so concurrent guesses cannot exceed the free failures, no more than four are checked at once per name, and a flood of made-up names evicts unlocked entries first and never clears a live lock for its age (`login_throttle.rs` unit tests; `services/http-gateway/tests/security_edge.rs::parallel_wrong_passwords_cannot_exceed_the_free_failures`). Compensating: the per-source allowance (a burst of 20, refilling at 0.5 a second) bounds how fast one address can keep a name locked. Rejected: locking per (source, name) pair, because under compose every source is the proxy's one address, so it would weaken the credential-stuffing defence for nothing. Residual: a client with many addresses, or any client under compose, can deny an operator's login until a second-factor-only recovery path exists (WP-56 or later). [VLD-ANB-MIDGARD-0019] |
| Administrator challenge exhaustion | Med | **MITIGATED** | `POST /api/v1/admin/challenge` must be unauthenticated: the challenge is how an administrator proves who they are. A flood once evicted every outstanding challenge from a shared 256-entry table (VLD-ANB-MIDGARD-0020). Each challenge is now bound to the administrator the request names and answerable only by them; each holds at most four, a fifth replacing their own oldest; names with no passkey are given a nonce but take no table entry; and past a global ceiling of 1,024 a new administrator is refused with 429 rather than anyone's challenge dropped. `services/http-gateway/tests/admin_enrolment.rs` proves the binding, the per-administrator bound, the unknown names and the ceiling. Residual: administrator names are not secret, and naming one needs no passkey, so a client that keeps requesting challenges for one named administrator keeps replacing that administrator's own challenges and can stop them completing a request while it continues; the per-source allowance (burst 20, 0.5 a second) slows it from one address, but under compose every client shares one address and a flood from many addresses is not bounded per source. The other administrators are unaffected, so dual control can proceed with another. Challenges are in memory and a restart clears them. [VLD-ANB-MIDGARD-0020] |
| Unauthenticated `/metrics` on the edge | Low | **ACCEPTED** | `GET /metrics` on the HTTP edge (7710) is served without a token so an in-enclosure scraper can poll it. It is bounded: request metrics are labelled by matched route template, never the request path (`route_label`), every family holds at most 1,000 series with drops counted in `metrics_series_dropped_total`, and label values are cut at 256 characters, so a client can neither grow the gateway's memory nor read back what it or others sent (VLD-ANB-MIDGARD-0003; `services/http-gateway/tests/security_edge.rs`, `services/telemetry/tests/telemetry.rs`). Compensating: network restriction; in the Helm chart the default-deny NetworkPolicy admits 7710 only from `console-edge` pods (`deploy/helm/midgard/values.yaml`), and a proxy that publishes the edge should not forward `/metrics`. The 9090 health ports are a separate item (WP-32). Residual: anything that can reach 7710 reads route-level request counts, latencies, connection outcomes and the availability SLO. [VLD-ANB-MIDGARD-0003] |
